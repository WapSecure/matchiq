# ADR-0011: Agent orchestration on Agent Framework workflows with a typed FSM

- Status: Accepted (2026-10-21). Refines spec §10, §28 and §46. Complements ADR-0012 (providers).

## Context

The spec asks for genuine multi-agent collaboration (Match Analyst → Narrative Writer → Fact Checker → Localization, Broadcast Producer), a state machine `DETECTED → ANALYZED → DRAFTED → VERIFIED` with REVISE and REJECT branches, and it warns that "a typed orchestrator with demonstrable agent collaboration is preferable to a fragile framework integration" (§10).

We checked the installed SDK (`agent-framework-core==1.22.0`) before deciding. The graph workflow API (`WorkflowBuilder`, `Executor`, `@handler`, `WorkflowContext.send_message` / `yield_output`, conditional `add_edge(..., condition=...)`) is exported without an experimental or release-candidate marker. Only the functional workflow API (`@workflow` / `FunctionalWorkflow`) is flagged `@experimental`. A prototype confirmed that typed messages (frozen dataclasses), conditional back-edges (a REVISE loop) and exception propagation behave as documented. One workflow instance cannot run concurrently.

## Decision

- Each roster stage is an Agent Framework `Executor` (`apps/agents/src/matchiq_agents/pipeline/executors.py`). The edges are wired in `pipeline/workflow.py`, which uses conditional edges for PASS / REVISE / REJECT and for writer failure. A fresh graph is built per request.
- Messages are one immutable, typed `PipelineState`. Every status change goes through `PipelineState.advance`, which enforces the service-side FSM in `pipeline/fsm.py`. SCHEDULED and PUBLISHED belong to the worker's deterministic gate.
- Model calls go through a `ModelPort`. Agent Framework `Agent` instances on `FoundryChatClient` or `OpenAIChatClient` (Ollama) implement it, and so does a deterministic `MockModel`. A `ModelRunner` around the port applies the per-call timeout derived from `deadlineMs`, at most two retries with exponential backoff, and a process-wide circuit breaker. Transport faults and timeouts trip the breaker. Output that parses but fails grounding is retried without tripping it.
- The Fact Checker is deterministic first: cited values, evidence ids, the entity allowlist, a forbidden-claim lexicon and length limits. An AI critique runs only after a deterministic PASS, and it can only add concerns. REVISE regenerates once. REJECT, or a second failure, falls back to verified templates, and to suppression if even the templates fail.
- The orchestrator wraps the workflow in a hard deadline plus grace period. Any exception or overrun yields a template-only `PipelineResult`. The service never returns an error for a model failure.

## Alternatives considered

- **Hand-written FSM only.** It is simpler, but it does not use the framework's orchestration, which the judging rewards. It would also duplicate routing that `WorkflowBuilder` already provides.
- **Agent Framework orchestrations (sequential, group chat, handoff) with `AgentExecutor`.** These pass chat transcripts between agents. Our hand-offs must be typed, immutable fact packets with deterministic gates between agents, so routing on free-form conversation would weaken grounding.
- **Functional workflows.** These are marked experimental in 1.22, so we rejected them for a deadline-bound release.

## Consequences

- The multi-agent design is visible in code and in traces: one `AgentRun` per stage and attempt, carrying the correlation id.
- The workflow API surface is pinned by `tests/test_providers.py::test_workflow_api_surface_is_available`. An SDK upgrade that breaks it fails CI.
- Building a graph per request costs a few milliseconds, which is negligible next to model latency.

## Addendum (2026-10-22): batched calls and a local-inference slow lane

Measured on an M1 Pro with Ollama 0.40.7 (`llama-server -np 1 -c 4096`), `qwen2.5:7b-instruct`.

**Where single-call latency goes.** Output tokens, not prompt size. The Match Analyst prompt is 453 tokens (844-character instructions, 955-character data block); prefill takes 0.05–0.2 s once the system prompt is cached (2.4 s cold). Generation runs at about 20 tokens/s. Strict `json_schema` output produced 220 tokens (11 s); JSON mode produced 105 tokens (5 s) but never the required shape, so it is not usable. Asking for minified JSON saved no tokens (222), and capping claims saved 20% of tokens but not wall time. Changing `num_ctx` reloads the model (4.5 s). Ollama's OpenAI-compatible `/v1/responses` honours `temperature` and `max_output_tokens`. It ignores `keep_alive` and `options`, whether sent through Agent Framework's `extra_body` or directly, so those are server settings (`OLLAMA_KEEP_ALIVE`, `OLLAMA_CONTEXT_LENGTH`). The earlier "33 s per Analyst call" came from calls queuing behind each other on the single slot.

**Call graph.**

|                        | Before                                                                                                                   | After                                                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Graph                  | analyst → writer → AI critique → localization × 3 locales (`asyncio.gather`, serialised by Ollama's one slot) → producer | analyst → writer → (AI critique, cloud only) → localization × 1 (every locale and persona in one call) → producer                                                            |
| Model calls, clean run | 7                                                                                                                        | 4 on `ollama`, 5 on cloud (mock eval p50 7 → 5)                                                                                                                              |
| Revision               | the whole draft set is rewritten                                                                                         | only the failing personas are rewritten; the drafts that passed are kept                                                                                                     |
| Final failure          | every persona falls back to templates                                                                                    | only the failing persona falls back; a failing (locale, persona) item gets its template when it states the same numbers and names, else the en-GB text with `localeFallback` |

- The Narrative Writer already wrote every persona in one call. A missing or contract-invalid persona no longer fails the whole call: the Fact Checker flags it, a revision asks for it, and in the end its template replaces it.
- A forbidden claim still rejects its draft outright, without revision. Shared issues (analysis, AI critique) still apply to every persona.
- The AI critique defaults off for `ollama` (`AGENT_CRITIQUE_ENABLED` blank = provider default). The deterministic Fact Checker always runs.
- Number words from English and phonetic Pidgin are now checked in fr-FR and es-ES too. Per-item acceptance exposed the gap: before, one bad item failed its whole locale.
- Model prose gets a deterministic clean-up: allowlisted names get their canonical capitals back, and hashtags are deleted. Neither edit can add a claim, and the checks run afterwards.
- The Writer, Localization and Producer no longer receive the engine's `rationale` and `counterEvidence` prose. Small models copied its wording and numbers ("two shots"). The Analyst still reasons over it, and the Writer now receives the analysis limitations.
- Data blocks are trimmed. A real packet carries about 28 metrics and 38 names (the whole squad list). Every prompt now names only the teams and the subject player, and the stages after the Analyst see only the metrics already cited upstream. The checks still use the full allowlist and evidence.
- Spelled-out numbers are rejected even when they match a value ("faiv" for 5), as the evaluation oracle already required: digits only.

**Slow lane.** `LIMITS.maxAgentDeadlineMs` and `AGENT_TIMEOUT_MS` now allow up to 180 s. Local inference needs minutes per insight, while cloud providers keep their short `AGENT_TIMEOUT_MS` by configuration. Templates are on air immediately, and the worker already upgrades them when a late verified result lands. For `ollama`:

- One call may use 0.75 of the deadline (0.5 for cloud). Inference is serial, and the batched Localization call is the longest stage.
- Timeouts have their own breaker counter (`AGENT_CIRCUIT_TIMEOUT_THRESHOLD`, default 8 consecutive) and no longer count as transport failures. A slow model is busy, not down. One pipeline times out at most twice before its deadline is spent, so 8 means about four pipelines in a row without one answer. Connection failures still open the breaker at `AGENT_CIRCUIT_FAILURE_THRESHOLD`.
- Output that parses but fails its checks is not retried (`output_retries=0`; cloud keeps 2). On local hardware a retry costs a full generation (10–25 s), and at low temperature it mostly repeats the same output. Each stage already has a deterministic recovery: the template analysis, the persona revision, or the per-item template.
- The service now answers within `deadlineMs` itself. Model work stops `grace_ms` early (1 s for cloud, 5 s for local), and the hard stop is the deadline, no longer the deadline plus grace. On a loaded machine, cancelling an in-flight Ollama call took up to 3.5 s past the old hard stop. That pushed the answer beyond the worker's HTTP timeout (`AGENT_TIMEOUT_MS` + 1.5 s), which would have triggered a needless retry.
- Temperature is 0.2, and output caps are set per agent (Localization 2,400 tokens), because truncated JSON fails to parse.
- The recommended profile is `AGENT_TIMEOUT_MS=120000`, `AGENT_JOB_CONCURRENCY=1` and `qwen2.5:7b-instruct` (see `.env.example` and the implementation log for the evaluation).

## Addendum 2 (2026-10-22): narrative quality, safe repairs and deadline-aware planning

Measured on the same M1 Pro with Ollama 0.40.7 and `qwen2.5:7b-instruct`, shared with other workloads. Evaluation methodology, failure taxonomy and results: `docs/ai/EVALUATION.md` and the implementation log.

**What the failure taxonomy showed.** Every rejection is now logged per stage, rule, persona and locale (`pipeline/diagnostics.py`). On the dev code, at a 120 s deadline, timeouts dominated: the Match Analyst took 41 s at p50 when it finished and timed out in 21 of 46 cases, so the Writer was left with no time in 38. The content rejections behind them were Analyst numbers that matched no metric (7) and spelled numbers (4), CASUAL bodies with two sentences (5), window lengths quoted from metric names (4) and translations that changed a number (3).

**Decisions.**

- **Prompts v2.** Rules are stated positively with the exact wording to use ("say 'recently'"). Each agent's output fields are described, and one grounded example from the golden case `sample_high_regains` is embedded. The example team is renamed Kestrel Vale, a name no fixture uses: a model that copies it fails the allowlist instead of attributing a statistic to the wrong real team. `tests/test_prompts.py` checks every example against the deterministic checks.
- **Input shaping.** The Analyst sees the six metrics most relevant to the insight kind and subject (`domain/relevance.py`). The ranking prefers the current window, then the kind's metric families, then the subject's side. The checks keep the full evidence, so citing any engine metric is still valid.
- **Deterministic repairs** (`guard/repair.py`) run before the checks and may only delete text or blur a window. They can drop trailing whole sentences to meet a persona limit. They can replace a window phrase with "recently", but only when its number is the window of an engine metric and not a cited value. They can also add an overlay `metricRef` when exactly one metric cited by the approved broadcast draft has that value. Each repair is recorded on `AgentRun.repairs`. A trimmed draft may lose a sentence that contained a violation; the kept text is checked on its own. When a window number coincides with a metric value, the guard cannot tell the two apart, and the text is left alone.
- **Feedback retries.** A rejected Analyst or Producer answer gets one retry. The retry receives each violation with its fix (`roster/notes.py`), and runs only while 60% of the deadline is left. The Writer's revision notes now carry the same fixes. Blind retries of rejected output stay off on `ollama`, and a timed-out local call is no longer retried: Ollama is serial, so a retry only waits longer.
- **Per-agent deadline shares (local).** These are shares of the whole deadline, bounded by what is left: Analyst 0.25, Writer 0.9, Localization 0.75, Producer 0.2. The Writer produces every agent narrative. A slow Analyst is cut short, because its template analysis still feeds the Writer.
- **Deadline-aware planning (local).** A process-wide `StageTimer` keeps a moving average of each agent's latency. A timeout counts at 1.25 times the time it used, because it is only a lower bound. The Analyst model call is skipped when the Analyst and Writer estimates together exceed the time left (reason `analyst: skipped to leave the writer time`). Without history, every stage runs.
- **Only requested personas are translated.** BROADCAST is still drafted for the overlay.
- **Governance.** `AgentRun` gains `promptHash` (SHA-256), `costEstimateUsd` (from `AGENT_PRICE_TABLE`; 0 for local, absent when unknown) and `repairs` (all optional, codegen regenerated). The prompt registry and its CI gate are described in `docs/ai/EVALUATION.md`. A deterministic broadcast-safety blocklist runs in every text check, and `ContentSafetyScreen` is the port for Azure AI Content Safety. It is not wired, and it fails closed once configured.

**Not changed.** No grounding rule was relaxed. Digits only, cited values, the entity allowlist, the forbidden lexicon and the persona limits all apply to the repaired text, and the independent oracle reports zero violations on every run.

**Consequence.** On a contended machine (prefill about 30 tokens/s instead of about 300, generation about 10 tokens/s instead of about 20), the four-call chain does not fit 120 s. Planning then trades the Analyst model call for Writer time. On a quiet machine, every stage runs.

**Note (2026-10-23, MQ-034): Localization covers every requested persona.** The live session `fx_comeback_42_s7` showed ANALYST and BROADCAST served as en-GB fallbacks in about 90% of fr-FR, es-ES and pcm-NG items, while CASUAL was translated. The v3 example showed only CASUAL items, and the model copied that item set. Localization prompt 4.0.0 adds `requiredItems` to the payload (every (locale, persona) pair, in order) and an example that translates all three Writer example drafts into all three locales, with its item count stated. The output is checked against `requiredItems`: each item left out is reported (`MISSING_ITEM`) and requested once more in a smaller follow-up call when the stage plan says it fits; anything still missing falls back per item, as a rejected item does. The guard also gains two tightenings: "twice" and "thrice" are spelled numbers, and a short non-quantifier word before "times" ("twi times") is rejected (`SPELLED_COUNT`). No grounding rule was relaxed.

## Addendum 3 (2026-10-23, MQ-060): editorial rules so key moments lead with the real story

**Context.** Session `fx_comeback_42_s7` was AI-written end to end with 0 grounding violations, yet the copy was wrong for broadcast. The 89' winner was headlined "Penbrook Town in final third" with the body "2 goals for Penbrook Town recently." (the value was `goals.away`, so the tally was also the other side's). The 42' goal was headlined "Equal shots for both teams", the 78' goal "Penbrook Town have a shot on target", and two momentum shifts printed "-0.19 in momentum" and "down to -1.11" to fans, under headlines that said the rising side was losing momentum. Replay `fx_comeback_42_s8` showed the standard wording was worse: headlines that were only the moment type ("Goal") and bodies that dumped every metric ("Final third entries (away) 1; final third entries (away) 1; …").

**Decision.**

- **Editorial rules** (`guard/editorial.py`) run on the canonical en-GB drafts and the overlay after the repairs, beside the grounding checks. Each violation is a revisable `SCHEMA_VIOLATION` (the copy has the wrong shape for its moment), so the persona gets one rewrite and then its standard wording, as before. Rules: a goal or red-card headline leads with the event (`EVENT_NOT_LEAD`); every headline names the subject and its event (`OFF_TOPIC_HEADLINE`); a goal headline carries no number but the score (`SECONDARY_STAT`); a rising moment is never told as a fall (`WRONG_DIRECTION`; the engine raises shot bursts, high regains, pressure and momentum swings only for the rising side); a goal gives the score from `goals.home` and `goals.away` in either order (`MISSING_SCORELINE`) and is never told as a tally (`GOAL_TALLY`); the scorer or dismissed player is named when the evidence names one (`MISSING_PLAYER`); Fan and Broadcast copy never shows an internal index value (`RAW_INDEX`), and Analyst copy shows one only in a sentence that names it (`UNLABELLED_INDEX`).
- **Internal indices are a contract.** `libs/contracts` gains `InternalIndexMetric` (`momentum`, `xT`, `pressureIndex`) and `isInternalIndexMetric`, exported to Python as `MetricDisplay` by codegen. Every other metric family is a display number. The rule checks numerals against the engine's index values; a numeral that equals a cited display number is left alone, because the guard cannot tell which one it states.
- **Safe repairs** (`guard/editorial_repair.py`), logged on `AgentRun.repairs` like the addendum 2 repairs: `LEAD_WITH_EVENT` replaces an off-topic goal or red-card headline, or a goal headline when the draft never gives the score, with the engine's event line ("GOAL — Penbrook Town lead 3–2"), the text the standard wording uses, and cites both `goals` metrics; `ADD_PLAYER` puts the engine's "Ola Mensah scores for Penbrook Town." first where the persona allows another sentence; `DROP_INDEX_SENTENCE` deletes a Fan or Broadcast sentence that shows an index when another sentence remains. A goal told as "2 goals recently" is never repaired: it is rejected.
- **Prompts.** Writer 3.0.0, Producer 2.1.0 and Analyst 2.1.0 get moment-type rules and one correct example per type (goal, red card, momentum, pressure, shot burst, high regains; `roster/examples.py`, checked by `tests/test_prompts.py`). The data block gains `subjectSide`, `opponentTeam` and `eventLine` (the engine's headline for a goal or red card), and the Writer and Producer always see the score metrics. Localization and the critique are unchanged.
- **Standard wording 2.0.0** (`templates/`): a real headline per moment type, the goal line with the score, one plain sentence per persona ("2 shots on target for Marshstead Albion recently."), each metric at most once, no zero-valued supporting facts, momentum in words for Fan and Broadcast and as a labelled index for Analyst, and the same cited metrics in every locale. The template analysis the Writer drafts from when the Analyst is skipped is now plain sentences too. The worker's own templates already led with the goal and score; their Broadcast momentum caption printed both indices and now says "{team} are on top".

**Not changed.** No grounding rule was relaxed. The editorial rules only add rejections; the repairs only replace a title with the engine's own line, prepend the engine's own sentence, or delete a sentence, and the grounding checks and editorial rules run on the result.

**Measured.** One live pair at a 120 s deadline on 10 cases (implementation log): before, 27 of 40 en-GB items on air broke an editorial rule (47 violations) at 51% agent share; after, 0 of 40, with 0 grounding violations in both. The after run's agent share fell to 3% because every Writer call but one timed out at a load average of 26–35 (3.5 at the start of the before run); no output was rejected on editorial grounds. The share effect still needs a quiet-machine run.

## Addendum 4 (2026-10-23, MQ-064): handoff records, a run budget and per-step spans

Spec §28 and §46 ask for a record of every transition between agents, not only every model call. `AgentRun` is one row per model call and carries no transition, decision or evidence, so it cannot show how the roster reached its answer.

**Decisions.**

- **`AgentStep` contract** (`libs/contracts/src/lib/trace.ts`). One record per roster stage the run passes through: step index, role (the five agents plus `TEMPLATE_FALLBACK`), prompt registry version and hash, provider and model, the FSM transition (`fromStatus` → `toStatus`), a decision (`PASS`, `REVISE`, `REJECT`, `FALLBACK`) with a reason code and short reason, `inputChecksum`, cited `evidenceEventIds` and `metricRefs`, tokens, latency, cost estimate, retries and the correlation id. `PipelineResult.steps` defaults to `[]`, so a worker can still read a service that predates it.
- **Input checksum.** SHA-256 of the canonical JSON (sorted keys, no whitespace, UTF-8) of the request digest plus the handoff state the stage received: status, route, analysis, drafts, verification, overlay, attempt count and revision notes. Run timings are excluded, so the same request and model output yield the same checksums, and a replay can be compared step by step.
- **Recording.** Each workflow executor other than `finalise` runs inside `StepRecorder.record` (`pipeline/steps.py`). The emergency template path records one `TEMPLATE_FALLBACK` step with reason `ORCHESTRATION_ERROR`. Steps are capped at 32 per run.
- **Central run budget** (`pipeline/budget.py`). The orchestrator creates one `RunBudget` per run from `AGENT_BUDGET_MAX_HOPS` (default 12), `AGENT_BUDGET_MAX_TOKENS` (60,000) and `AGENT_BUDGET_MAX_COST_USD` (0.50), all validated at startup. Each step is a hop, and every model attempt charges its tokens and priced cost. Once a limit is reached, the model runner refuses further calls. Each stage then takes its existing deterministic fallback, the step records `FALLBACK` with reason code `BUDGET_EXCEEDED`, and `fallbackReason` says which limit was hit. A normal run takes at most 7 hops, so the default never binds outside a fault. Cost only counts deployments with a configured price; unpriced cloud calls are still bounded by tokens.
- **Tracing.** Each step is an OTel span named `invoke_agent <role>` with the GenAI semantic-convention attributes `gen_ai.operation.name`, `gen_ai.agent.name`, `gen_ai.system`, `gen_ai.request.model`, `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens`, plus `matchiq.correlation_id`, `matchiq.run_id` and the step decision, reason code and checksum. The span is a child of the request span, which continues the worker's `traceparent`. Without an exporter (ADR-0019) the API tracer is a no-op.
- **Storage: a table, not a JSONB column.** The worker stores steps in `agent_steps` (migration 0008), keyed `(org_id, correlation_id, step_index)`, with the RLS policy of ADR-0018. A JSONB column on `agent_runs` was rejected: those rows are per model call, so steps would be duplicated or attached to an arbitrary call, and a correlation-id lookup would have to unpack JSON. Rows are append-only (`ON CONFLICT DO NOTHING`), and the fixture foreign key cascades on retention.
- **API.** `GET /api/v1/agents/traces/{correlationId}` (spec §29) needs `agents:traces:read` and reads under the caller's organisation, so another tenant's run answers `404 trace-not-found`.
- **Web.** The fact-checks page shows "How the agents worked on this" on each moment: role, decision and reason in plain words, time taken and the evidence cited. Model, prompt version and hash, checksum, tokens and cost are in Technical details.

**Not changed.** Agents still return proposals only, and the worker's publish gate still decides. A step's evidence lists what the stage cited; it is not a second grounding check.
