## 1. Executive summary

The specification contains **976 distinct requirements** across its 58 sections (extracted by eight independent read-only reviewers; every row cites source evidence on `origin/dev`). **403 (41.3% of all rows; 403/957 applicable) are verified complete.** For the hackathon's P0 requirements the figure is **309/472 = 65.5%**. Enterprise (post-hackathon) scope is **2/110 = 1.8%** verified, which is expected: most of it is explicitly deferred by ADR-0030 to ADR-0036.

**What is strong.** The deterministic core is genuinely well built and tested in CI: the typed event contract, the append-only ledger, the football engine, deterministic replay (re-confirmed live today: 1,388 of 1,388 events identical across two sessions), the evidence-grounded multi-agent pipeline with deterministic fact-check and publish gate, the overlay scheduler, editorial controls with audit, OIDC with role-based access and Postgres row-level security, the design system, and the CI quality and security gates.

**What blocks a confident submission.** Nothing in the product core, but several deliverables and demonstrations are missing or fragile:

1. The sub-two-minute **demo video is not recorded** and the **Innovation Studio form is not submitted** (owner actions; required).
2. **No hosted demo** (owner decision, no ADR); judges must run the local stack, and no CI job proves a clean clone boots.
3. **Manual approve-before-air is unusable at replay speeds** (cues expire in about 1 s at 5×); the fix (MQ-081) is **not merged** and its work is unpushed in a worktree.
4. **Live AI-written narratives were not demonstrated on current `dev`**: in two replays run today under load or overlap, 0 of 30 published moments (15 per replay, excluding the ruled-out goal) were written by the model (all fell back to standard wording). The committed baseline shows 73% agent share on a quieter run. This must be re-measured on a quiet machine before the video is recorded.
5. **Microsoft Foundry and Azure have never been exercised** (no subscription). Honestly labelled everywhere, but it weakens the Microsoft-technology story.

**Bottom line.** The product is a credible, honest hackathon submission whose engine and safety architecture are verified, but it is not yet submission-complete (video, form, approval window, live-AI demonstration) and is nowhere near enterprise-production-ready (no hosting, DR, load testing, billing, tenancy admin, provider licensing, or Azure deployment).

## 5. Verified completed features

- **Event contract and ledger:** strict discriminated event union, idempotent ingest with 202/409/422, unique sequence/event keys, ledger immutability trigger, transactional outbox, RLS on every tenant table, 12 consistent migrations.
- **Football engine and replay:** deterministic counting, time-weighted possession, bounded momentum, P0/P1 key-moment rules, corrections refold, seeded generator with six fixtures, replay controller with golden and property tests; determinism re-confirmed live (1,388 of 1,388 events).

- **Product surface:** lobby with paging, studio, recap, fact-checks, activity log, Player Focus, producer controls, on-air preview with burned-in synthetic label, ruled-out goal handling end to end (runtime-observed), plain-language errors, design system.
- **Security and governance:** OIDC with six roles and deny-by-default RBAC (403 and RFC 9457 bodies confirmed live), strict CSP and security headers (confirmed live), CodeQL, Trivy, SBOMs, secret and dependency scans, append-only audit log, 36 ADRs.

## 20. Architecture inconsistencies

- Three agent rosters and two state machines in the spec (§10, §28, §46); the code follows §28; `DEAD_LETTER`, `RETRYING` and the Tactical Interpreter have no equivalent and no ADR.
- Event names differ between §8 and §25 (resolved by ADR-0004); resource names (`fixtures` vs `matches`), approve route, `/state` vs `/snapshot`, overlay field names and SSE event names differ between spec sections and the contract.
- **Overlay cue windows are match-clock while approval is a human, wall-clock action**; this is the root of the MQ-081 defect.
- `canTransitionOverlay` exists and is unit-tested but is never called by api, worker or web: overlay state is changed ad hoc.
- Two ingest paths with different validation depth (API ingest vs worker replay).
- Number/name checks implemented twice (Python and TypeScript) without one generated source (only the lexicon is shared).
- Two ADRs numbered 0023; ADR-0024 to 0029 skipped; ADR-0033 understates that a sequence gap does mark state provisional.
- Several docs are stale: ARCHITECTURE_RULES (lists built libraries as planned), IDENTITY_AND_ACCESS (preferences guard), THREAT_MODEL test references, traceability REQ-036/038 contradiction, overlay latency stated as 3 s in §14 and 4 s in §44, `docs/api/README.md` idempotency wording.
